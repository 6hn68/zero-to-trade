# AI 开发流程（agentic engineering 版）

> 2026 年 10 月 31 日，90 路逆向 vibe coding 打法 + 红队冲击后的 v2；2026 年 11 月 7 日并入公开仓库时只做了匿名化与数字更新，规则本身没动。
>
> 这份文件是给贡献者的工作流，不是给新手的教程。新手从 [00-getting-started.md](00-getting-started.md) 开始，别从这里开始。
> 总口径：我们抄的不是 vibe coding 原教旨（Karpathy 亲口限定"周末小玩具"，2026 年 4 月 30 日已亲手弃用改叫 agentic engineering），
> 而是工程化那一边的纪律。对外一律自称 **agentic engineering**。
> v1 的 plan 门被红队打下来了（prototype 期搞四件套=过早优化）——v2 全部降级为**条件触发**。

## 二分法（先定这条，再谈别的）

- 🟢 **纯自用、损害可控的一次性小工具**：随便玩，轻量流程。
- 🟡 **进公开仓库 / 碰用户数据 / 密钥的代码**：走下面全部护栏。
- 🔴 **触钱（支付/收款/报价引擎）、触生产（生产库写/真实客户数据）、触身份（登录/权限）**：强制工程化——人读 diff + 安全扫描 + 测试 + 双账户权限测试，缺一条不许上。

zero-to-trade 现在 14 个脚本文件约 9,000 行、零依赖，还在 🟢/🟡 区；但终态（AI 自动找客户→报价→收款）必中 🔴。按"黄灯+工程化打底"现在就建。

## plan 门（条件触发，不是默认）

**只有命中任一条件才出 plan**，没命中直接干：
1. 改动 ≥3 个文件
2. 动数据、密钥、或不可逆操作
3. 范围模糊（"优化一下""顺手改改"这类）
4. 不熟悉的模块（第一次碰的代码区）

plan 只写两样，不写技术方案（维护者批的是意图，不是代码）：
1. **意图**：要解决什么问题、改完长什么样（一句话+验收标准）
2. **验收标准**：怎么证明改对了

维护者只回"意图行不行"。回"行"才动手。

prototype 期（无外部用户）豁免：单文件 / <30 行 / 纯文本，干完一句话汇报就行。

## 新功能开工前（Connor 验证框架）

1. 先写数据结构（JSON/字段），再写代码。
2. 有竞品/参考：截它的关键界面喂给 AI，模仿风格不 reinvent。
3. 上线前砍到只剩核心：能进 / 能看懂 / 能完成关键动作 / 能付费——AI 会诱导多做一点，人负责砍（张三疯两步生死法）。

## 执行纪律

- 按 plan 动手；动手发现 plan 要改，先停下来同步，不许悄悄偏离。
- 一次只做一件事，改完即验，不攒到最后。
- 修 bug 先写复现测试，无复现不许动手；**同一问题 AI 改第 3 次还失败→立刻人工接管，禁第 4 轮补丁**。
- 新依赖安装前 `npm view` / `pip index versions` 三秒核验（E404=枪毙；发布<30天/无 maintainer=高危人工看）；agent 装包必须人工点头。
- commit 信息写人话：改了什么 + 为什么。一个 AI turn 一个 commit；大重构前 `git tag good-<日期>`。
- 禁止 AI 跑破坏性命令：`rm -rf` / `git reset --hard` / `git checkout .` / `git clean -fd` / `git push --force` / `drop`。

## Final Reviewer（按二分法分档）

🟢 轻量：跑通 + `git diff` 扫一眼（多改/调试代码/硬编码密钥三看）。
🟡/🔴 完整：全量测试 + diff 逐行复查 + 对验收标准打勾 + **必须交付的硬性证据**：
1. 最小复现命令
2. 根因行号
3. 修复 diff
4. 验证日志原文
5. 回归测试结果
6. 信息不足先交"需补充信息清单"，不许编

## 红线（六条，AI 只能产出草稿，签字永远是人）

1. **支付密钥/财务操作**：AI 只生成支付参数，扣款走 webhook + 人工逐笔核对。
2. **生产数据库**：AI 只读账号（REVOKE DELETE/DROP）；生产/开发物理隔离；删改走人工审批。
3. **对外发布**：只生成草稿，维护者点确认才发；push 公开仓库/发版必须逐条批。
4. **身份认证与权限**：auth 用成熟方案（不许 AI 手写）；auth 相关 PR 逐行人工审。
5. **私钥/证书**：只进保险库/环境变量，永不进仓库；pre-commit 跑 secret 扫描；疑泄露立即轮换（删文件≠安全）。
6. **有法律后果的操作**（合同/承诺/付款）："是 AI 干的"不是抗辩，签名/发送永远人工。

外加三条铁律：**生产凭证不进 agent 上下文；破坏性命令人工按键；用户数据访问策略人手实测。**

项目约束：只用 Python 标准库；密钥/支付/生产数据 AI 不碰不读不写。

## 复盘

按 Reflexion：出问题 → 二值打分（成/没成）→ 一句话复盘（哪一步错、下次换什么动作）→ 写进 skill 的 `insights/`，不碰 SKILL.md 正文。同一坑第二次出现就升级手段。
