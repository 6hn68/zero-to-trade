# ADR-001：plan 门从"默认全开"降级为"条件触发"

- **状态**：已采纳（2026-10-31）
- **背景**：v1 的 dev-flow-ai.md 规定"任何新功能、任何改动逻辑的代码先出 plan，维护者回'行'才动手"，plan 含改动文件清单/架构影响/测试方案/回滚方案四件套。90 路逆向 vibe coding 后，红队 9 路（机会成本）+ 2 路（plan 门官僚化）联合打下来。
- **决策**：plan 门降级为条件触发——只有命中（≥3 文件 / 动数据或密钥 / 范围模糊 / 不熟悉模块）任一条件才出 plan；plan 只写意图+验收标准，不写技术方案；维护者只批"意图行不行"。prototype 期（无外部用户）重仪式冻结，豁免线保留。
- **理由**：
  1. zero-to-trade 当时是 3 个脚本 ~120 行、零依赖、无人使用的 prototype，v1 的四件套是过早优化（"别让适应工具的时间超过从工具获益的时间"）。
  2. 维护者不读代码是硬约束，让他批技术方案=橡皮图章，批意图才是有效把关。
  3. 降级≠砍掉：条件命中时 plan 门全量生效；Final Reviewer 的证据清单保留。
- **后果**：v0.3 报价引擎开工时若命中"≥3 文件/不熟悉模块"，仍走 plan 门。

- **后续（2026-11-07）**：报价引擎已落地为 `scripts/quote_engine.py`（v0.2 alpha），不再是"开工时"；仓库现为 12 个脚本文件约 6,300 行。ADR 的结论不变——plan 门仍是条件触发，不是默认全开。
