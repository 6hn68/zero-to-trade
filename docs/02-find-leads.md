# 02·找客户 Find Leads

> **本环节目标**：搞出一条每天能稳定冒出 20 条真线索的渠道组合，攒够 200 条原始名单。
> **一句话原理**：客户不是「找」来的，是「筛」出来的。一条路走到黑迟早断粮，多开几条路才稳。

## 一、为什么这一步排在最前

新手最大的幻觉，是以为自己缺「客户资源」。

真相是：但凡一个品类有进口量，里面那些真在采买的贸易商、经销商、连锁店、车队，绝大多数不会蹲在 LinkedIn 上等你私信；也几乎没有公司会把「正在找中国供应商」写在官网首页。

> **数字从哪来（别拍脑袋）**：目标国一年进多少、主要从谁手里进，去 UN Comtrade（comtradeplus.un.org）按「报告国 + HS 编码 + 年份」拉年度进口记录，或者翻目标国海关/统计局的公开进口统计页。查到就把来源和统计时间抄下来；查不到就填【示例】占个位，千万别自己编个顺眼的数。

所以找客户不是搜索，是筛。从一堆公司名里筛，别管它名头多响，只认三件事：它现在买不买、买不买得起、你够不够得着。

三个硬标准，缺一条就是假线索：
1. **有真实采购迹象**——网站上有产品目录、有批发价目、有业务联系页，不是只有一张首页图的公司。
2. **有进出口相关痕迹**——做过进口、挂过展会、写过跟供应商合作的内容。
3. **有可触达的联系人**——要拿到**具体人的姓名** + 他的个人邮箱或 WhatsApp/电话。只拿到公司名不算线索；只拿到 `info@` / `sales@` / `support@` 这类公共信箱，等同于没拿到人，降为「待挖人」而不是合格线索。

一天 20 条，不是一天发 20 封开发信。20 条**筛过的**线索，和 20 个随便搜来的公司名，命中率根本不是一个量级。

## 二、分步操作

**第 0 步：先划清合法边界（这一步没做完，后面全是白做）**

找客户只能用**公开信息**。本环节允许的信息源，和 [03·背调客户](03-due-diligence.md) 的合规红线完全一致：

允许的：

- 企业官方网站（公司信息、产品目录、联系方式、成立声明）
- 公开海关/进出口数据（UN Comtrade、各国官方统计机构、持牌商业数据平台的公开查询功能）
- LinkedIn 公开主页（职位、公司信息、公开动态）
- 公开的展会参展商名录、行业协会/商会会员名录、公开黄页
- 公司官方渠道发布的新闻稿与官方社媒账号

禁止的：

- 社工库、被泄露的联系人名单、被盗数据库
- 购买个人隐私数据（个人手机号、私人邮箱、住址等）用于开发
- 冒充身份套取信息、收买或贿赂对方员工拿客户名单
- 抓取、镜像违反平台服务条款的网站内容

**为什么这条没得商量**：向他人出售或提供公民个人信息、以及非法获取此类信息，情节严重的构成**侵犯公民个人信息罪**（《中华人民共和国刑法》第 253 条之一），是刑事责任，不是「行业惯例」。外贸新人最容易踩的坑是「买一份目标国采购联系人名单」——便宜、快，但那是把公司和你自己一起送进去。

一句话原则：**你能光明正大打开的网页，才算信息来源。** 需要「特殊手段」才能拿到的数据，不进线索表，也不进客户档案。

---

**第 1 步：铺渠道（七路清单，含点击路径与是否要钱）**

这七条路，先都走一遍，再决定重点押哪几条。**至少同时跑通 4 路**——只押一条，哪天那路一断你就没米下锅。

| # | 渠道 | 点击路径（照着点） | 能拿到什么 | 免费 / 要钱 |
|---|---|---|---|---|
| 1 | **海关 / 进口数据** | 免费版：UN Comtrade（comtradeplus.un.org）→ 选 Goods → 填报告国 + HS 编码 + 年份 → Preview。付费版：持牌商业海关数据平台 → 搜 HS 编码或产品关键词 → 导出进口商名 + 供应商 + 柜量 | 真实在进口的公司名、品类、量级、来源国 | **免费版无进口商名；带公司名的商业库要钱**（各家覆盖国家与价格自查） |
| 2 | **Google 搜索语法** | 直接在搜索框敲下面第 1 步附的语法串，逐条跑 | 官网、经销商页、名录 PDF、联系方式 | **全免费** |
| 3 | **目标国进口商名录 / 黄页** | 搜 `{国家} yellow pages`、`{国家} chamber of commerce member directory`、`{国家} importers association`，进站点后按行业分类筛 | 公司名、地址、电话、行业分类 | **以免费为主**，少数协会名录需注册或会员费 |
| 4 | **LinkedIn** | 搜索框输公司名 → 切到 Companies → 进公司页 → 点 People → 用 `purchasing / procurement / import / sourcing / owner` 逐个筛 | 采购负责人姓名、职位、在职状态 | **免费账号够用**（可发好友邀请附短消息）；Sales Navigator 是付费升级 |
| 5 | **展会名录** | 展会官网 → 找 Exhibitor / Exhibitor List / 参展商名录 → 常见是 PDF 或可按国家筛选的页面 → 按品类 + 国家筛 | 常年参展的活跃买家名单、产品线 | **以免费为主**，个别展会需注册后下载 |
| 6 | **B2B 平台** | Alibaba / Made-in-China / GlobalSources 等 → RFQ 或买家频道 → 按国家 + 品类筛 | 买家询盘、买家名片 | **免费看有限信息，深度信息要会员费** |
| 7 | **同行 / 竞品官网的经销商页** | 找同品类里已进目标国的品牌官网 → 找 `Where to buy / Distributors / Dealer locator / 经销商` → 按国家筛 | 当地**已经在卖同类货**的现成渠道 | **全免费**（最容易被忽视的一路） |

> 第 7 路多说一句：竞品官网的经销商页，等于别人免费替你筛好了「当地谁在卖」。品类、价位、渠道角色全现成，基本是七路里最省力的一路。

**附：Google 实操语法（直接复制，替换括号里的内容）**

```
site:{国家域名} "tyre importer"                       # 限定国家域名 + 精确词组
intitle:"tyre" "importer" {国家} -alibaba             # intitle 命中标题，-alibaba 排除平台噪声
"TBR" "wholesale" "distributor" site:.ae             # 多个精确词组叠加
"importer" "{品类词}" "contact" -alibaba -amazon      # 找带联系方式的进口商页
filetype:pdf "exhibitor list" {品类} {国家}           # 直接找名录 PDF
"{本地语言的进口商词}" {城市}                          # 小语种本地词，命中率常高于英文
```

语法要点：

- `site:` 限定站点或国家域名（`.sa` `.ae` `.eg`），但会漏掉用 `.com` 的本地公司，**只当辅助，不当主力**。
- `intitle:` 只搜网页标题，比正文命中准得多，是筛「这家主打什么」的最快方式。
- `"引号"` 是精确词组，不加引号会被拆词，结果全是噪声。
- `-词` 排除。搜进口商时**一定要带上 `-alibaba -amazon -aliexpress`**，否则一半结果是平台页面。
- `filetype:pdf` 直接捞名单类 PDF，展会名录和协会名录常以 PDF 发布。

**日课配比（按条数，不是按百分比）**：每天 20 条拆成

- 海关数据 **8 条**（名单主力）
- 搜索 + 官网 **6 条**（补联系方式，含上面 6 条语法串）
- 经销商页 / 黄页 **3 条**（补品类与渠道角色）
- LinkedIn **2 条**（挖具体的人）
- 展会名录 **1 条**（补漏与校验）

任何一路断了，其余四路还能顶上。**不要**把 20 条全押在海关数据上——那正是坑 1。

**第 2 步：先定准 HS 编码，再拉海关数据（最耗时，但最值）**

HS 编码定错，后面全白做。取数路径按这个顺序查，不要凭记忆写编码：

1. **WCO 的 HS 数据库**（wcoomd.org 的 HS Nomenclature）+ 本国海关总署的税则查询页，确认品类的章与子目（轮胎类多在 HS 40 章下，**具体子目必须自己查证，不要照抄本文档**）。
2. **目标国海关官网的 tariff 查询页**，确认对方国家的归类口径——同一产品在不同国家的子目可能不一致。
3. 仍不确定：**问货代或申请预归类**，拿到书面归类意见再批量拉数。

编码定下来后，拉目标国进口记录，重点看三列：

- **谁在进口**：公司名 → 这就是名单主体
- **进口量级**：从高到低排，大概率是你的目标客户
- **来源国结构**：如果大量从中国进口，说明他们对中国货熟，门槛低

拉一批出来后做初筛，命中任一条就**降级并在 `note` 里写明原因**（不要直接删，留着再核）：

- 一次进口量小到只做样品
- 频繁换供应商
- 公司名里只有贸易字样、但查不到实体地址或仓库
- 官网与海关记录的公司名对不上

**第 3 步：找到官网 + 补全信息（每条线索 3-5 分钟）**

拿到公司名后先找官网。最快的两条路径：

1. Google 搜 `"公司全名"`，或用 `site:{国家域名} "公司全名"` 排除同名公司。
2. 搜不到官网 → 回第 1 步的第 3、7 路（黄页 / 竞品经销商页）反查，很多小贸易商根本没有独立官网。

找到后重点看三处：

- `/contact`、`/about`、`/products` 页面——找**具名**邮箱、电话、WhatsApp、地址
- 产品目录里有没有你要卖的品类（比如 TBR 商用胎、OTR 工程胎）
- 有没有「批发 / 经销 / 代理商 / distributor / dealer / wholesale」相关表述——决定他是渠道商还是终端用户

顺手记一条「情报」：对方主打什么品牌、价位带大概在哪、有没有提到自己的仓库或门店数量。这些是后面写开发信和报价时的弹药，**写进 `note` 字段**（脚本会按关键词计分，见第 6 步）。

**5 分钟止损规则**：一条线索 5 分钟还拿不到任何联系方式，就先停下——把公司名、`country`、`product`、`source` 和「待补联系方式」写进 `note` 存进表，**不要继续挖**。它会被脚本自动判为 T3（信息不足先养着），等你攒够一批 T3 再集中补。单条死磕 20 分钟是新手最常见的时间黑洞。

**第 4 步：LinkedIn 找对的人（免费账号先跑通，别急着买付费）**

点击路径：搜索框输公司名 → 切到 **Companies** → 进公司主页 → 点 **People** → 在筛选框里逐个试 `purchasing`、`procurement`、`import`、`sourcing`、`owner`。

```
# LinkedIn 人搜语法（直接在搜索框敲）
"purchasing manager" "tyre" {国家}         # 职位 + 品类 + 国家
"procurement" OR "sourcing" {公司名}        # OR 是并集，能同时命中两个职位词
"import manager" -"sales" {国家}            # - 排除销售岗，销售岗不是你要找的人
```

- **免费账号**：能搜、能看、能发好友邀请（可附一段短消息）。先把这条路跑通。
- **付费 Sales Navigator**：更强的筛选与 InMail 额度。**等你确认这条路真能出人再买**，不要第一天就订阅。
- 中东很多小公司决策链极短，找到采购总监基本就等于找到决策人；Owner / Founder 在小公司就是他本人拍板。
- 加好友的请求语一句说清身份和来意，**不要一上来发产品目录**。
- 找不到人时，用「公司名 + 邮箱格式猜测 + 验证」补。验证只做**格式校验与域名 MX 检查**这类公开技术手段；**验证不过的邮箱不要群发**，退信率会拖垮整个域名信誉。

**邮箱有效性硬规则**（第 3 条硬标准的实操版）：

> 下表邮箱域名统一用保留域名 `sample.example` 作占位示范，实际记录时替换为你查到的域名。

| 邮箱类型 | 判定 | 处理 |
|---|---|---|
| 具名个人邮箱（如 `a.rahman@sample.example`） | **有效** | 记入 `email`，可联系，`contact` 填对应姓名 |
| 部门信箱（`purchasing@sample.example` / `procurement@sample.example` / `import@sample.example`） | **半有效** | 记入 `email`，`note` 标「部门信箱」，优先级低于具名邮箱 |
| 公共信箱（`info@sample.example` / `sales@sample.example` / `support@sample.example` / `contact@sample.example`） | **不算拿到人** | 可以记，但 `note` 必须标「仅公共信箱」，不进优先联系序列 |
| 个人免费邮箱（gmail / hotmail / yahoo）作为**唯一**联系方式 | **存疑** | `note` 标红旗，交给 [03·背调客户](03-due-diligence.md) 重点核 |

**第 5 步：展会名录做补漏和校验**
公开的展会参展商名录是可以合法获取的公开资料。用途有两个：
- **补漏**：不在海关数据里但参展过的贸易商
- **校验**：连续两三年参展的，说明还在正常经营

把参展商的「国家 + 产品线 + 是否贸易商」记下来。

**第 6 步：按脚本的真实列名建表（这一步决定了你能不能自动分级）**

所有线索统一进一张 CSV。**表头必须严格用 `scripts/lead_score.py` 读取的这 9 个列名**（脚本按列名取值、不区分大小写，多写的列会被直接忽略）：

| 列名 | 必填？ | 填什么 | 脚本怎么用 |
|---|---|---|---|
| `company` | **必填** | 公司全名 | 缺这列脚本直接报错退出 |
| `country` | 建议填 | 国家 | 支持 `--country` 参数筛选 |
| `product` | 建议填 | 对方经营的品类（如 `TBR 12.00R20`） | 参与采购信号关键词命中 |
| `source` | 建议填 | `referral` / `trade_show` / `customs` / `linkedin` / `search` 五选一 | 来源可信度 30 分（`referral` 30 → `search` 10）；**填这五个以外的词一律按 10 分算** |
| `email` | 可选 | 邮箱 | 有则加分；**格式不合法就直接不算联系方式**，等于白填 |
| `phone` | 可选 | 电话 | 有则加分；**数字少于 7 位当成没填** |
| `contact` | 可选 | 对接人**职位或姓名**（如 `purchasing manager`） | 参与采购信号命中，命中「决策角色」组得 3 分 |
| `years` | 可选 | 成立年数 | 填数字最稳（`18`）；`18年`、成立年份（`2010`）也能认。**写成「十年」这类没有阿拉伯数字的会被当 0**，白丢 10 分 |
| `note` | 可选 | 备注 | 采购信号的主力字段，写品牌、价位带、门店数、进口记录等弹药 |

四个最容易翻车的地方，照着做，别省：

1. **列名是 `contact`，不是 `contact_role` / `联系人`。** 写成别的名字脚本读不到，采购角色那组分永远拿不到，评分会系统性偏低而你还不知道为什么。
2. **WhatsApp 号要写进 `phone` 这一列**，并且带上 `wa` 或 `whatsapp` 字样（如 `+000 00 000 0000 (WhatsApp)`）。另开一个 `WhatsApp` 列脚本读不到，WA 加分不会触发。
3. **采购迹象要写进 `note` / `product` / `contact`**——脚本只扫这三列找关键词（如 `rfq`、`tender`、`container`、`purchasing manager`）。另开「采购迹象强度」列无效；**写在 `company` 公司名里的品类词也不算分**（脚本故意不扫公司名，避免线索自己给自己加分）。
4. **「待补」「未知」「N/A」这类占位词等于空**。脚本把 `-` / `na` / `待定` / `待补` / `未知` 等都视为没填，别用它凑格子。

存成 `my_leads.csv`，跑：

```
python scripts/lead_score.py my_leads.csv
python scripts/lead_score.py my_leads.csv --country Saudi
python scripts/lead_score.py my_leads.csv --format detail
```

**关于分级的口径，别搞混**：

- 本环节（和 [03·背调客户](03-due-diligence.md)）打的是 **A/B/C 客户评级**——判断这家值不值得投入。
- `lead_score.py` 输出的 **T0-T3** 是「先联系谁」的排序工具，不是客户评级，别直接当成 A/B/C 抄进档案。
- A/B/C → T0-T3 的映射口径由 [04·建联客户](04-outreach.md) 唯一定义，本环节不要自行另立标准。

**第 7 步：定日课节奏（把「找客户」变成日常动作，而不是项目）**

| 项目 | 建议值 | 说明 |
|---|---|---|
| 每天线索量 | **20 条**（按第 1 步的 8/6/3/2/1 拆到渠道） | 是「筛过的 20 条」，不是「搜到 20 个公司名」 |
| 每天时长 | **固定 30 分钟**（建议早上 9 点） | 到点就停，不因手感好而拖长 |
| 单条时间上限 | **5 分钟**（见第 3 步止损规则） | 超时就标「待补联系方式」存 T3 |
| 每周验收 | 5 天 × 20 条 = **100 条/周**，周末跑一次脚本分级 | 一个月约 400 条，足够喂给背调环节 |
| 阶段目标 | 累计 **200 条**原始名单后进 [03·背调客户](03-due-diligence.md) | 200 条 ≈ 10 个工作日，不要为了凑数放宽三条硬标准 |

渠道纪律比渠道聪明更重要：**宁可每天只做 30 分钟，也别做一次 8 小时然后停一周。**

## 三、判断标准

本环节「做好了」的硬标准：

- **至少 4 路**渠道（第 1 步七路清单里的）已实际跑过并出过线索，不押单一来源。
- HS 编码已在 WCO / 本国海关 / 目标国海关任一官方源核实过，不是凭记忆写的。
- 每条线索都过三硬标准：有真实采购迹象 + 有进出口痕迹 + 有可触达联系人，缺一条不入表。
- 只拿到 `info@` 类公共信箱的，已标「仅公共信箱」，**未计入**「已拿到可触达联系人」。
- 线索 CSV 的表头**严格用了脚本的 9 个列名**（`company/country/product/source/email/phone/contact/years/note`），且 `contact` 没被写成别的名字。
- 每条线索标了 A/B/C 初评级，且理由写进 `note` 可追溯（评级口径与定义见 [03·背调客户](03-due-diligence.md)）。
- 无效邮箱、未验证邮箱已剔除，未进入群发；负向信息（停业/诉讼/制裁）已检索一轮。
- **全部信息源公开合法**：无社工库、无购买的隐私数据、无冒充套取。
- 每天固定 30 分钟采集，已连续执行 **10 个工作日**不断档（约 200 条原始名单）。

## 四、AI 提示词

**提示词 1：从公司官网提取关键信息**

```
You are a B2B lead researcher. I will paste the raw text of a company website (mostly English or
Arabic). Extract ONLY facts that are explicitly stated. Never infer or guess.

Output EXACTLY this structure, and write "NOT STATED" if a field is absent:

1. Company legal name & brand names
2. HQ address + all branch addresses listed
3. Products they sell (list up to 10, with size/type if given, e.g. "TBR 12.00R20, 315/80R22.5")
4. Positioning clues: do they sell wholesale / retail / own brand / distribute others' brands?
   Quote the exact sentence as evidence.
5. Whether they mention importers, export, sourcing from Asia/China, or annual exhibitions (quote it)
6. Contacts: email, phone, WhatsApp, contact form URL, LinkedIn URL
7. Estimated company size signals (number of employees, number of locations, "leading/largest"
   claims) — quote exact wording
8. Red flags: generic mailbox only (gmail/hotmail/yahoo as sole contact), no physical address,
   site looks unfinished, brand claims unverifiable

Be strictly factual. My downstream decision is whether to invest backoffice time on this lead.
Invented details are worse than blanks.
```

中文说明：这段让 AI 把一个官网正文变成结构化字段。核心就两句：只准写页面上白纸黑字写了的；八个字段固定输出。这样每条线索长得一样，能直接进表。红旗字段专门喂给下一步背调。

**输出怎么落进线索表**（对应第 6 步的 9 个列名）：

| 提示词输出项 | 落进哪一列 |
|---|---|
| 第 1 项公司名 | `company`（记得加【示例】前缀） |
| 第 2 项地址 → 国家 | `country`；完整地址写进扩展表 |
| 第 3 项产品 | `product` |
| 第 4、5、7 项（定位 / 进出口 / 规模） | 压缩成一句话写进 `note` |
| 第 6 项联系方式 | 邮箱 → `email`；电话/WhatsApp → `phone`；职位 → `contact`；官网 → 扩展表 |
| 第 8 项红旗 | 追加进 `note`，交给 [03·背调客户](03-due-diligence.md) |

> 别把官网地址塞进 `product` 或 `note` 之外的列——脚本不读 `website`，塞进去也不会加分。

**提示词 2：线索优先级批量排序**

```
You are a sales operations analyst. Below is a table of 25 potential buyers for a Chinese tire
exporter targeting {country}. Score and rank them.

For EACH company produce a one-row table with:
- Priority (A = contact within 3 days, B = within 2 weeks, C = backlog/nurture)
- Fit score 0-10 (product match + import evidence + size signals)
- Contactability 0-5 (did we get a named person or a working channel?)
- Confidence 0-1 (how sure are you that this company still trades and is a real importer)
- ONE next action, written as a concrete instruction (not "research more") —
  e.g. "Find Purchasing Manager on LinkedIn, send InMail in EN, ask for 2025 import volume"

Then output:
- TOP 5 with a 2-sentence justification each
- BOTTOM 5 with the single reason to deprioritize
- A note listing which companies had UNVERIFIED claims in their input

Rules: use only information present in my table. Do not invent company facts. If my data is
insufficient, lower Confidence rather than inventing detail.
```

中文说明：这段用来避免「看着顺眼就都标 A」。它强制 AI 给置信度，并且必须给「下一步具体动作」而不是空泛建议。同时把数据不足的公司主动暴露出来，提醒你要去补信息而不是硬发。

**提示词 3：搜索策略生成器**

```
You are an OSINT research planner for B2B export lead generation in the tire industry
(target market: {country}).

Design 12 concrete search queries I can run, mixed deliberately across four sources:
A) Google/Bing web search  B) LinkedIn people/title search  C) trade-fair exhibitor directory
D) customs/import-data platform filters

Rules:
- Queries must be realistic, copy-paste-able strings. Use the local language where useful.
- Include at least 4 queries using import/HS/product terminology rather than generic words.
- Include at least 3 queries designed to find NEGATIVE signals (lawsuit, complaint, sanction,
  "closed", "ceased operations", "no longer active") so I can screen dead companies.
- For each query state: source, what it should surface, and how many results I should expect
  to keep (be realistic, not optimistic).

Also list 4 query patterns that are USELESS in this market and say why — I want to avoid
the search traps I am likely to fall into.
```

中文说明：这段用来一次性拿到一整套搜索策略，特别包含「找负面信号」的查询——很多人只搜好话，搜到已停业、被告、被制裁的公司还当新线索发信，这是纯浪费。第 4 部分「无效查询模式」能直接告诉你哪些坑别踩。

## 六、新手常见坑

**坑 1：只做海关数据一条路**
- 现象：花两天拉了 300 条海关记录，盯着屏幕美滋滋，然后卡住不动了。
- 原因：海关数据只有公司名和贸易记录，没有邮箱、没人、没有产品细节——它只是个名单入口，不是终点站。
- 正确做法：海关数据只当「名单入口」用。按第 1 步的日课配比，海关那 8 条必须配上其余 12 条补全动作，才算跑完完整一轮。

**坑 2：拿到公司名就算完成线索**
- 现象：表里 300 行，全是公司名，联系人栏一片空白，跟没填一样。
- 原因：把「找到公司」当终点，没意识到开发信发到 info@ 等于对着公司前台喊话，前台哪有权采购。
- 正确做法：入库前必须填到具体的人。找不到人的，降级成 B 类并标「待挖人」，别占着 A 类的坑。

**坑 3：群发同一个邮箱格式**
- 现象：猜了 200 个 `firstname.lastname@sample.example` 格式的邮箱，一次性轰出去，退信率 60%。
- 原因：猜错的邮箱被硬发，把域名信誉一起拖下水，后面真能进的邮件也跟着进垃圾箱——自己把自己埋了。
- 正确做法：小批量试（每次 10-20 个）先验证，退信率超过 10% 立刻停。宁可发 50 个准的，也别发 200 个里那 140 个假的。

**坑 4：只看「有没有网站」，不看「网站说什么」**
- 现象：看到个英文页面就当优质客户，跟看人家门面气派就觉得有钱一样。
- 原因：现在网站大半 AI 生成，看着挺像回事，其实一句采购信号都没有。
- 正确做法：看产品目录、看有没有列品牌、看批发/经销表述、看成立年份。有网站 ≠ 在做进口，这俩不是一回事。

**坑 5：靠展会名录当唯一来源**
- 现象：抄了一份展会参展商名单就开始群发。
- 原因：参展商名录是「愿意花钱曝光的公司」，同一家公司会出现在多个展会，且部分公司已停业。
- 正确做法：展会名录只占日课里的 1 条（约 5%），且必须用「连续参展年份 + 官网活跃度 + 海关记录」三重校验后再入库。

**坑 6：不定时采集，三天打鱼两天晒网**
- 现象：忙的时候一个礼拜没碰，手感全无。
- 原因：把找客户当项目而不是当日常动作。
- 正确做法：把它绑死在每天固定时间段。渠道纪律比聪明重要：宁可每天只做 30 分钟，也别憋一次 8 小时然后停一周。

**坑 7：只找不记，搜完就关网页**
- 现象：一下午搜了几十家，关掉浏览器，第二天一家都想不起来，名单表还是空的。
- 原因：把「看过」当成「拿到」。线索唯一的家就是** CSV 里那一行**，不是你脑子里的一点印象。
- 正确做法：搜到一家就立刻开表填一行，哪怕只填 `company` / `country` / `source` / `note` 四个格子。**没进表等于不存在。** 宁可一天记 20 条完整的，也别「看过」100 家。

**坑 8：专挑大国企、大集团下手**
- 现象：专找名片最气派的那几家，发完信石沉大海，两周后心灰意冷。
- 原因：大集团有成熟供应商、有年度招标、有层层审批，新人从零撬，基本撬不动——不是你信写得差，是入口压根不对。
- 正确做法：把「会不会理你」也当筛选条件。优先找**决策链短的公司**：中小贸易商、家族企业、Owner 直接拍板的小公司。等你在目标国攒下 2-3 个成交案例，再回头攻大集团。

**坑 9：把经销商当成进口商**
- 现象：找到家公司官网卖轮胎，就当进口商，上去就谈价格和柜量。
- 原因：没分清渠道角色。经销商只从本地批发拿货，不报关、不订柜，你跟他谈 FOB/CIF、谈 40HQ 配柜，他根本做不了主。
- 正确做法：入库时就把渠道角色写进 `note`——**进口商 / 经销商 / 零售商 / 终端车队**。看三样：官网有没有「批发/经销/代理」表述、海关记录里有没有报关、竞品经销商页上是不是标着 distributor。角色不同，后面报价和话术完全两码事（见 [06·报价](06-quote.md)）。

## 七、可复制模板（照填，不依赖 AI）

**模板 1：线索主表 `my_leads.csv`（表头与 `scripts/lead_score.py` 完全一致，可直接喂脚本）**

```
# 本表全部为虚构示例数据（仅用于教学演示）。公司名带「【示例】」前缀、邮箱使用保留域名 sample.example、电话为占位符，均不对应任何真实企业或真实联系人。请勿据此联系。
company,country,product,source,email,phone,contact,years,note
【示例】海湾轮胎贸易,Saudi Arabia,"TBR 12.00R20, PCR tubes",customs,purchasing@sample.example,+000 00 000 0000 (WhatsApp),purchasing manager,18,"Annual RFQ for truck tyres, looking for supplier, 40HQ container regular. Importer, 3 warehouses"
【示例】迪拜轮毂行,UAE,"PCR 195/65R15, alloy rims",trade_show,,+000 00 000 0001,buyer,9,"Met at Gulf Oil Show, asked for quotation, 20GP trial order. Distributor, no import record"

```

复制要点（三条别写错，写错了脚本会静默少算分）：

- 列名就是上表这 9 个，**一个字都不要改**（尤其 `contact` 不要写成 `contact_role`）。
- `source` 只能填 `referral` / `trade_show` / `customs` / `linkedin` / `search` 之一。
- `years` 只填数字；WhatsApp 号写进 `phone` 并带 `WhatsApp` 字样。

**模板 2：扩展信息表（脚本不读的字段，另开一张，用 company 做关联键）**

```
company,website,channel_role,priority(A/B/C),status,next_followup,language,owner
```

> 把「跟进状态 / 下次跟进 / 官网 / A-B-C」放这里，是为了让主表保持脚本能直接读的干净结构。两张表用 `company` 关联，不要往主 CSV 里塞一堆脚本读不懂的列。

**字段填写口径：**

- `source`：`referral` / `trade_show` / `customs` / `linkedin` / `search`
- `priority`：A = 3 天内联系 · B = 2 周内 · C = 养着（口径与定义见 [03·背调客户](03-due-diligence.md)）
- `channel_role`（扩展表）：进口商 / 经销商 / 零售商 / 终端车队——见坑 9
- `note`：品牌 / 价位带 / 仓库门店数 / 进口记录 / 红旗，能写多具体写多具体（脚本在这里找采购信号关键词）

**三硬标准自检（每条入库前打勾）：**

```
公司名：____________  采购迹象 □   进出口痕迹 □   可触达联系人 □
联系人姓名：________  邮箱类型：具名 □ / 部门 □ / 公共信箱 □
渠道角色：进口商 □ / 经销商 □ / 零售商 □ / 终端 □
信息来源是否公开合法：是 □（否 → 不入库）
```

跑一遍看结果：

```
python scripts/lead_score.py my_leads.csv --format detail
```
